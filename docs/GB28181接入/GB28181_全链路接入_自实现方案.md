## 2. 总体架构（自实现后的数据流）

```
 国标IPC(SIP)
      │ REGISTER / KEEPALIVE / INVITE
      ▼
 WVP 信令平台(18080)──────────► 调 ZLM openRtpServer 收流口
      │                              │
      └─ 设备按 SDP 把 PS/RTP 推到 ZLM 30002-40000
                                           │ GB28181Process 解 PS
                                           ▼
                              ZLM ──► rtp/{设备_通道} 出流
                                           │
        ┌──────────────────────────────────┼──────────────────────────┐
        │  前端(flv.js) ◄ ws://zlm:9992/rtp/{流}.live.flv              │
        │  分析器 ◄ rtsp://zlm:9994/rtp/{流}  (avformat_open_input)     │
        │  easySVA后端(若依) ◄── 轮询WVP接口 + ZLM getMediaList 同步状态 │
        └───────────────────────────────────────────────────────────────┘

 easySVA后端 ──(点播/取消)──► WVP /api/play/start|stop ──► 触发 INVITE 与开收流口
```

> **关键设计：easySVA 后端不接管 ZLM hook，也不实现 SIP**。它是 WVP 的**客户端**：从 WVP 拉设备/点播，用**轮询**同步在线状态。这样既不破坏 WVP（它依赖 hook 鉴权/点播），也不动 ZLM 源码。

## 3. 关键设计决策（先定，避免返工）

### 3.1 用哪个字段区分设备类型？
- 现有前端/后端已用 `stream_source_type`（`DIRECT`/`PLATFORM`）。
- 决定：**新增 `device_type`（`RTSP`/`GB28181`）作为前端区分字段**；同时国标设备把 `stream_source_type` 置为 **`PLATFORM`**（表示"流来自平台推送"，不走 `addStreamProxy`）。
- 后端内部**按 `device_type` 分流**：
  - `RTSP`（含现有 DIRECT）→ 走现有 `addStreamProxy` 路径（**完全不动**）；
  - `GB28181` → 走 WVP 路径。
- 结果：现有 RTSP/DIRECT 设备零改动，满足"只增不改/不破坏"。

### 3.2 流命名
| 类型 | ZLM app | streamId | 拉流(分析器) | 预览(前端) |
|---|---|---|---|---|
| RTSP/DIRECT | `live` | `{apeId}` | `rtsp://zlm:9994/live/{apeId}` | `ws://zlm:9992/live/{apeId}.live.flv` |
| **GB28181** | **`rtp`** | **`{设备ID}_{通道ID}`** | `rtsp://zlm:9994/rtp/{流}` | `ws://zlm:9992/rtp/{流}.live.flv` |

- GB28181 的 streamId 由 **WVP 生成**（实测为 `{设备}_{通道}`，如 `34020000001320000001_34020000002320000001`）。
- 判断"流是否上线"：`GET http://zlm:9992/index/api/getMediaInfo?secret=..&vhost=__defaultVhost__&app=rtp&schema=rtsp&stream={流}`，`code==0` 即上线。

### 3.3 在线状态同步
- **双源**：① WVP 设备/通道状态（online/keepalive）；② ZLM `getMediaList` 是否有 `rtp/{流}`。
- 后端**轮询**（每 N 秒，可配）刷新 `h_device.status`（`ONLINE`/`OFFLINE`）与 `is_online`。
- 不接管 ZLM hook（hook 保持在 WVP，WVP 点半播/鉴权靠它）。

### 3.4 WVP 鉴权放行
- 沿用已在 WVP 打的补丁（`app=rtp` 默认放行）。**本方案只在文档里说明，不改 WVP 之外的鉴权。** 若以后把 hook 移到后端，需在后端复刻该放行逻辑（见 §9 风险）。

### 5.3 新建 WVP 客户端 `WvpClient`
文件 `ruoyi-admin/.../waring/service/impl/WvpClient.java`（新类，包内直接用 RestTemplate）：
- `login()`：`GET /api/user/login?username=..&password=..`，用返回的 cookie/token。
- `listDevices()`：`GET /api/device/list` → 设备列表。
- `listChannels(deviceId)`：`GET /api/device/channel/list/{deviceId}` → 通道列表。
- `playStart(deviceId, channelId)`：`GET /api/play/start/{deviceId}/{channelId}` → 触发 INVITE + ZLM 开收流口；返回 `{streamId, playUrl, rtsp}`。
- `playStop(streamId)`：`GET /api/play/stop/{streamId}`。

```java
@Repository
public class WvpClient {
    private static final Logger log = LoggerFactory.getLogger(WvpClient.class);
    private final RestTemplate restTemplate;
    private final WvpServerMapper wvpServerMapper;
    @Autowired
    public WvpClient(RestTemplate rt, WvpServerMapper mapper){ this.restTemplate=rt; this.wvpServerMapper=mapper; }

    private WvpServer server(){ WvpServer s = wvpServerMapper.selectEnabledById(1L); if(s==null) throw new ServiceException("未配置可用WVP服务器"); return s; }
    private String base(){ WvpServer s=server(); return "http://"+s.getHost()+":"+s.getApi_port(); }

    /** WVP登录: 返回可能需要的 token/cookie（多数接口无需，以版本为准） */
    public void login(){ WvpServer s=server();
        String url = UriComponentsBuilder.fromUriString(base()+"/api/user/login")
            .queryParam("username", s.getUsername())
            .queryParam("password", s.getPassword()).build(true).toUriString();
        ResponseEntity<String> resp = restTemplate.getForEntity(url, String.class);
        if(log.isDebugEnabled()) log.debug("WVP login resp: {}", mask(resp.getBody()));
    }

    /** 拉WVP设备列表 */
    public JsonNode listDevices(){
        String url = base()+"/api/device/list?page=1&count=1000";
        JsonNode root = readJson(url);
        return root.path("data");
    }
    /** 拉某设备通道 */
    public JsonNode listChannels(String deviceId){
        String url = base()+"/api/device/channel/list/"+deviceId+"?page=1&count=1000";
        return readJson(url).path("data");
    }
    /** 点播：触发INVITE，返回 {streamId,rtsp,wsFlv} */
    public Map<String,Object> playStart(String deviceId, String channelId){
        String url = base()+"/api/play/start/"+deviceId+"/"+channelId;
        JsonNode data = readJson(url).path("data");
        Map<String,Object> m = new HashMap<>();
        m.put("streamId", data.path("streamId").asText(""));
        m.put("rtsp",     data.path("rtsp").asText(""));
        m.put("wsFlv",    data.path("wsFlv").asText(""));
        return m;
    }
    public void playStop(String streamId){
        if(StringUtils.isBlank(streamId)) return;
        String url = base()+"/api/play/stop/"+streamId;
        restTemplate.getForEntity(url, String.class);
    }

    private JsonNode readJson(String url){
        ResponseEntity<String> resp = restTemplate.getForEntity(url, String.class);
        String body = resp.getBody();
        try { return new ObjectMapper().readTree(body); }
        catch(Exception e){ throw new ServiceException("WVP接口返回异常: "+url); }
    }
    private String mask(String s){ return s==null?null:s.replaceAll("(?i)password=[^&]*","password=***"); }
}
```
> ⚠️ WVP 2.7.x 各版本的 `/api/device/list`、`/api/play/start` 返回结构略有差异；**以你部署的 WVP 实际返回为准**，把 `data.path("...")` 字段名对上即可。`play/start` 的返回里一般含 `wsflv`/`rtsp`/`streamId`。

### 5.4 `HDeviceServiceImpl` 增加 GB28181 分支
> 现有 `getDirectLiveUrl`/`startMonitor`/`stopMonitor`/`previewMonitor` 都是 DIRECT-only。增加一个 `buildGb28181PlayUrl` 帮助方法，并在这些方法里按 `device_type` 分流。

```java
private boolean isGbDevice(HDevice d){ return d!=null && "GB28181".equalsIgnoreCase(d.getDevice_type()); }

/** GB28181 点播: 触发WVP play → 返回 ws-flv, 并把 streamId/playUrl 写回库 */
private Map<String,Object> buildGb28181Play(HDevice device){
    if(StringUtils.isBlank(device.getGb_id()) || StringUtils.isBlank(device.getGb_channel_id()))
        throw new ServiceException("国标设备缺少 gb_id/gb_channel_id");
    Map<String,Object> play = wvpClient.playStart(device.getGb_id(), device.getGb_channel_id());
    String streamId = String.valueOf(play.getOrDefault("streamId",""));
    String wsFlv = String.valueOf(play.getOrDefault("wsFlv",""));
    if(StringUtils.isBlank(wsFlv)){
        // fallback 按约定拼: ws://zlm:9992/rtp/{streamId}.live.flv
        ZlmServer z = resolveEnabledZlmServer(device);
        if(z!=null && StringUtils.isNotBlank(streamId))
            wsFlv = "ws://"+z.getHost()+":"+z.getMedia_http_port()+"/rtp/"+streamId+".live.flv";
    }
    if(StringUtils.isNotBlank(wsFlv)) hDeviceMapper.updatePlayUrlByApeId(device.getApe_id(), wsFlv);
    Map<String,Object> r = new HashMap<>();
    r.put("apeId", device.getApe_id());
    r.put("playUrl", wsFlv);
    r.put("streamId", streamId);
    r.put("monitorStatus", "RUNNING");
    return r;
}
```

### 5.6 判断国标流是否上线的工具（复用现有 ZLM 调用风格）
```java
private boolean zlmStreamOnline(HDevice d){
    if(StringUtils.isBlank(d.getGb_id())) return false;
    String stream = d.getGb_id()+"_"+StringUtils.nvl(d.getGb_channel_id(),"");
    ZlmServer z = resolveEnabledZlmServer(d);
    if(z==null) return false;
    String url = UriComponentsBuilder.fromUriString("http://"+z.getHost()+":"+z.getApi_port()+"/index/api/getMediaInfo")
        .queryParam("secret", z.getSecret())
        .queryParam("vhost","__defaultVhost__")
        .queryParam("app","rtp")
        .queryParam("schema","rtsp")
        .queryParam("stream", stream).build(true).toUriString();
    try {
        JsonNode root = new ObjectMapper().readTree(restTemplate.getForEntity(url,String.class).getBody());
        return root.path("code").asInt(-1)==0;
    } catch(Exception e){ return false; }
}
```

## 9. 已知坑 & 风险（务必先看）

| # | 坑 | 处理 |
|---|---|---|
| 1 | WVP `media.id` ≠ ZLM `mediaServerId` → 找不到 mediaServer | WVP `media.id` 必须 `= Aodpt9CbTmrRBOMv` |
| 2 | `on_publish` 鉴权拒绝国标流（auth failed） | 已打 WVP 补丁（`app=rtp` 默认放行）；**若把 hook 移到后端须在后端复刻** |
| 3 | WVP 多实例抢 5060 | 只起一个 WVP；`kill` 所有旧 `wvp-pro-*` |
| 4 | redis 残留 `VMP_SIP_INVITE_SESSION_INFO` → "在途"卡死 | `DEL` 相关 redis key + 单实例 |
| 5 | 流格式：国标推 **PS-over-RTP**（非 TS） | 自建源用 `ps_rtp.py`；ZLM 只认 PS |
| 6 | 流前缀：文档曾写 `live/{id}`，**实际是 `rtp/{流}`** | 统一用 `rtp/`；后端返回为准 |
| 7 | WVP `2.7.x` 接口返回字段名因版本而异 | `WvpClient` 里 `data.path("...")` 以部署版本核对 |
| 8 | 在线判定单源会误判 | 双源：WVP online + ZLM `getMediaList` |
| 9 | `rtp/{流}` 60s 无读者 TTL | 点播后保持有拉流者；或配置 `auto_close` |
| 10 | 国标密码明文 | `gb_password` 不返前端；建议加密存库 |
