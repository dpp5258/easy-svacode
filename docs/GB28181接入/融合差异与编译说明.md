# GB28181 国标接入 · 融合差异与编译说明

> 记录 G28181国标接入 分支与 main 的差异来源、融合策略，以及一处编译修复，避免他人拉取后编译失败。

---

## 一、分支定位

- **`G28181国标接入`**（本分支）= **我的 WVP 后端正** + **main 团队版睡岗(YOLO-Pose)算法/文档/SQL/工具**。
- 与 **`main`** 的唯一实质差别 = **GB28181 后端"设备源"** 的实现方式不同（见下）。

---

## 二、与 main 的差异（融合策略）

| 维度 | 本分支 | main | 说明 |
|---|---|---|---|
| 设备/通道/点播来源 | **WVP REST**（`WvpClient`：登录/设备/通道/play/stop） | **ZLM `/index/api/gb/*`**（`Gb28181MediaClient`/`GbDeviceSyncTask`/`Gb28181Channel`） | 真实 ZLMediaKit **无内置 GB 模块**，main 的 ZLM-gb-api 路可能不通；WVP 路已验证可跑 |
| 国标拉流地址 | **`rtp/{设备}_{通道}`**（`DeploymentAnalyzerClient.buildStreamUrl` 对国标设备做分流） | `live/{apeId}`（无国标分流） | `rtp/` 为 WVP/ZLM 实测出流名 |
| 服务器配置表 | 新增 **`wvp_server` 表**（WVP 连接）+ `WvpServer/Mapper` | 扩展 `ZlmServer` 字段 | 配置 WVP 连接 |
| 同步机制 | `HDeviceServiceImpl.@Scheduled syncGbDevices`（走 WVP） | `GbDeviceSyncTask`（quartz，走 ZLM）+ `syncGbOnlineStatus` | 本分支统一走 WVP |
| 控制器 | 本分支 `HDeviceController`（自有点播/预览） | 增加 `/gb/remote-channels`、`/gb/import`、`/live/gb/{apeId}` 等 | — |
| DB schema | `h_device` 国标字段 + `wvp_server` 表 | `sql/gb28181_backend_up/down.sql` | — |
| **睡岗算法** | **与 main 一致**（已并入 YOLO-Pose 引擎 + C1/C2/C3 睡姿状态机） | 同 | **相同** |

> **融合结论**：保留 **WVP 设备源**；删除 main 的 **ZLM-gb-api 后端**（`Gb28181MediaClient`/`GbDeviceSyncTask`/`Gb28181Channel` 及 `/gb` 端点）；并入 main 的 **睡岗算法与文档**。

## 三、⚠️ 编译修复（必须）

**`SVA-server/Analyzer/Core/GenerateAlarmVideo.h`** 使用了 `std::string`（`struct Alarm` 的 `controlCode/alarmId/...` 成员），但**没有 `#include <string>`**（只 include 了 vector/queue/mutex）。部分编译环境因间接 include 恰好通过，部分会报：

```
error: 'string' in namespace 'std' does not name a type
error: 'struct SVAAnalyzer::Alarm' has no member named 'controlCode' ...
```

**修复**：在该头文件顶部补一行：

```cpp
#include <string>
```

已在 `/opt` 与 `G28181国标接入` 分支中修复，`mvn` 后端与 CMake 分析器均编译通过。

## 四、睡岗（YOLO-Pose）运行说明

- 模型：`/opt/SVA/models/yolo11n-pose.onnx`（1×56×8400，`decoder=pose(56ch)`）。用 `scripts/install_pose_model.sh <模型路径>` 接入。
- 分析器启动即加载（`初始化 on_yolo11n_pose`），`total ONNX models loaded: 3`，`Start Success`。
- 布控用 `algorithmCode:"on_yolo11n_pose"` + `behaviorRules:[{"behaviorType":"sleep",...}]` 触发睡姿状态机：
  - **C1/C2** 低头睡（`hdThreshold` 默认 0.12；`thresholdMs` 为 t_suspect，默认 15s）。
  - **C3 趴桌**（`hd ≤ θ_desk=0.0` 持续 `T_desk=1.5s`）。
  - **躺卧兜底**：旧平台"横躺宽高比"（`distanceThresholdPx`，默认 1.2）在 pose 未命中时生效。
