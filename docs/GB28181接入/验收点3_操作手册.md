## 二、逐条验收操作与预期

### ① 国标 IPC SIP 注册(5060)、平台看到设备 —— ✅
**操作**：登录平台 → 进入「设备管理」页。
**预期**：
- 列表出现设备 `34020000001320000001`（名称 `GB28181-CLIENT`），类型列显示 **GB28181**，在线徽标 **在线**。
- 接口佐证：`GET /prod-api/waring/device/list` 返回该设备 `device_type=GB28181`、`status=ONLINE`、`gb_channel_id=34020000002320000001`。
**佐证日志（WVP）**：`[设备上线] deviceId：34020000001320000001`、`[注册成功]`、`[收到通道]设备: 34020000001320000001 -> 1个`。
> 说明：SIP 信令(5060 注册/保活/INVITE)由 **WVP** 承担；ZLMediaKit 无内置 SIP。

### ② backend 扩字段 + 从 WVP 同步国标设备列表 —— ✅
**操作**：查看「设备管理」中国标设备的字段，或直接查数据库。
**预期**：
- 接口返回含 `device_type/gb_id/gb_channel_id/gb_domain/channel_count/status/sip_server` 等新增字段。
- 数据库 `h_device` 表存在上述列；存在 `wvp_server` 表（WVP 连接配置）。
- 定时任务(每10s)自动把 WVP 设备+通道 upsert 进 `h_device`，`ape_id` 唯一键保证不重复。
**佐证**：设备列表里国标设备每设备仅 1 行；`reboot`/等 10s 后仍稳定存在。

### ③ sva-server 兼容国标流、视频预览 —— ✅
**操作**：「设备管理」→ 国标设备行点「预览/实时」→ 播放器出画面。
**预期**：
- 播放地址为 ws-flv：`ws://<zlm>:9992/rtp/{设备}_{通道}.live.flv`（注意是 **rtp/** 前缀）。
- 接口佐证：`GET /prod-api/waring/device/monitor/{apeId}/preview` → 返回 `deviceType=GB28181`、`playUrl=ws://…/rtp/{流}.live.flv`。
**佐证**：WVP `[点播成功]`；ZLM `getMediaList` 有 `rtp/{流}`（ts/rtsp/rtmp/fmp4）；命令行验流：
```bash
ffprobe rtsp://10.122.205.66:9994/rtp/34020000001320000001_34020000002320000001
# → h264 704x576 25fps
```

### ④ 设备上下线状态同步到平台页 —— ✅
**操作**：
1. 停掉模拟设备 → 等约 10~15s（一个同步周期）→ 平台该设备状态变 **离线**。
2. 再启动设备 → 等约 10s → 状态回 **在线**。
**预期**：`/prod-api/waring/device/list` 中该设备 `status` 在 `ONLINE` ↔ `OFFLINE` 变化；`is_online` 1 ↔ 0。
> 说明：以 **WVP 的 Online** 为准，不会因"当前没有点播流"误判为离线。

### ⑤ RTSP 设备不被破坏（回归） —— ✅
**操作**：设备列表应有原 RTSP 设备 `cam979722`；对其「预览」应能播。
**预期**：
- 预览返回 `streamSourceType=DIRECT`、`playUrl=ws://…/live/cam979722.live.flv`、`monitorStatus=RUNNING`。
- 其布控仍 `rtsp://…:9994/live/cam979722`（未改走国标路径）。
**佐证**：上述字段与部署列表确认。

## ⚠️ 验收材料表述修正（重要）
若验收方案写"**基于 ZLMediaKit 内置 GB28181 服务实现**"为**错误**——ZLMediaKit 主库**没有内置 GB28181 SIP 服务**。
→ 应表述为"**ZLMediaKit(媒体) + WVP(信令)**"组合实现。

  -H "Authorization: Bearer $TOKEN"

  -H "Authorization: Bearer $TOKEN"
