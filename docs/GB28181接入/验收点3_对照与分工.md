验收材料写"**基于 ZLMediaKit 内置 GB28181 服务实现**" —— **不成立**：ZLMediaKit 主库**没有内置 GB28181 SIP 服务**（只有 `GB28181Process` 解 PS 的媒体能力）。SIP 信令（5060 注册/保活/INVITE）需由 **WVP**（或独立 SIP server）承担。
→ **正确方案**：**ZLMediaKit(媒体) + WVP(信令)**。请把验收方案改为该表述，否则第1条无法达成。

## 接口交付（给其它角色）
- **后端**：
  - 设备流名：国标= `rtp/{设备_通道}`（如 `34020000001320000001_34020000002320000001`）
  - 播放地址：`rtsp://{zlm}:9994/rtp/{设备_通道}` / `http://{zlm}:9992/rtp/{设备_通道}.live.flv`
  - ZLM 查询：`getMediaList` / `getMediaInfo`（判定在线/上线）
  - ZLM hook：`on_publish`/`on_stream_changed`/`on_rtp_server_timeout` → 同步设备状态；把 `[hook]` 指向能放行国标流的后端（或按 WVP 补丁放行）
  - **WVP 配置要点**：`media.id` = ZLM `[general] mediaServerId`；否则 WVP on_publish 报"找不到 mediaServer"
- **分析器/前端**：按上述流地址拉流/预览（与现有 RTSP 一致，无需区分 GB/RTSP）。
